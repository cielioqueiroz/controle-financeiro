# Validação da importação com Auth e Data API reais

Data: 17/10/2026. Resultado: **aprovado**, 21 verificações.

Branch Git: `codex/integridade-importacao-leitura`. Branch Neon:
`codex-integridade-20261016` (`br-billowing-mud-ac8q493y`), expira em 23/10/2026.
Migração `0008` aplicada apenas nessa branch. Nenhuma alteração em produção.

## O que foi exercitado

| Cenário | Evidência |
|---|---|
| Auth real | Cadastro, saída, entrada com senha e sessão de dois usuários sintéticos na execução final. Sessão restaurada após reload. |
| Rollback HTTP | Transação com `kind` inválido devolve `23514`; conta e documento não permanecem. |
| Concorrência HTTP | Duas chamadas simultâneas pelo adaptador real: uma salva, a outra reconhece duplicata. Duas ocorrências idênticas continuam distintas. |
| Leitura real | Contagem exata, dois registros e 2.468 centavos; conferência original com versão, contagem, critério e diferença zero preservados. |
| RLS com JWT real | Segundo usuário não lê documento nem transações do primeiro. O mesmo conteúdo pode ser salvo por ele sem virar duplicata de outro titular. |
| PDF e interface | PDF inteiramente sintético lido pelo pdf.js e pelo parser Nubank existente; uma compra de 789 centavos confere com o gabarito. |
| Resposta perdida | A RPC conclui com HTTP 200, mas o navegador recebe uma falha controlada. A prévia é preservada ao navegar; nova tentativa reconhece duplicata e o Painel passa de R$ 24,68 para R$ 32,57 sem F5 ou nova requisição de documento HTML. |
| Histórico | A tela real mostra o nome do PDF e a conferência original salva. |
| Sem credenciais | SDK sem sessão falha; POST direto sem JWT é recusado com HTTP 400 e `missing authentication credentials`. Esse é o contrato observado deste serviço, sem presumir 401/403. |
| Restrição do ensaio | Rede do navegador limitada aos dois hosts da branch e ao endereço local. Nenhuma chamada a Neon de produção. |

O teste usou o SDK instalado e os módulos reais de persistência, sem dublês.
O validador não grava senhas ou tokens em arquivos ou logs; os contextos do
navegador são descartados ao terminar. As credenciais sintéticas são gerenciadas
pelo Auth real da branch de teste.
Os usuários e documentos sintéticos permanecem somente na branch temporária,
que já possui expiração; nenhuma linha existente foi removida.

## Repetir enquanto a branch existir

Validador: [`scripts/validar-rpc-real.py`](../../scripts/validar-rpc-real.py).
Ele fixa os hosts de teste e falha se o frontend tentar alcançar outro Neon.

Conferir no Neon que a branch mantém verificação de e-mail no cadastro e login
desligada. O endereço `http://127.0.0.1:5178` foi adicionado aos domínios
autorizados **somente da branch de teste**; a primeira tentativa foi recusada
como `Invalid origin` antes dessa configuração.

Da raiz, em PowerShell, iniciar o frontend sem alterar `.env.local`:

```powershell
$env:VITE_NEON_AUTH_URL='https://ep-sparkling-hill-acpltupk.neonauth.sa-east-1.aws.neon.tech/neondb/auth'
$env:VITE_NEON_DATA_API_URL='https://ep-sparkling-hill-acpltupk.apirest.sa-east-1.aws.neon.tech/neondb/rest/v1'
npm run dev --workspace frontend -- --host 127.0.0.1 --port 5178 --strictPort
```

Em outro terminal, também na raiz:

```powershell
uv run --with playwright python scripts/validar-rpc-real.py
```

Cada execução cria novas identidades fictícias em `example.invalid`. A saída
sanitizada fica em `node_modules/.cache/validacao-rpc-real-resultado.json`.
O PDF é criado em memória e não entra no repositório.
